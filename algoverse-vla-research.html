Teaching Robots
to Self-Correct.

Can a robot policy that has already failed be steered into recovering with natural-language feedback? I built the GPU evaluation infrastructure to test that question rigorously on a 7B-parameter Vision-Language-Action model.

Problem

Vision-Language-Action (VLA) models such as OpenVLA map a camera image and a language instruction ("pick up the black bowl and place it on the plate") directly to robot-arm actions. They learn by behavior cloning from expert demonstrations, which means they only ever see examples of success. Once deployed, a policy that drifts into an unfamiliar state cannot notice its mistake or adapt.

In large language models, self-correction works best when the model gets reliable external feedback. A physics simulator can supply exactly that: it knows where the gripper ended up, where the object is, and whether contact happened. Our team asked whether that simulator-grounded feedback, turned into a natural-language diagnosis and fed back into the policy's prompt, could help a failed robot recover.

What an episode looks like

Approach

A three-stage pipeline wrapped around OpenVLA's official LIBERO evaluation loop and run serverlessly on Modal GPUs. The hooks are switched off by default, so with no flags set the evaluation behaves exactly like stock OpenVLA.

Every failed episode is replayed twice from the same MuJoCo snapshot and RNG seed. The two runs differ only in the prompt, so any difference in outcome can be credited to the language feedback.

A diagnosis is grounded in the measured end-effector, gripper, and object positions rather than guessed. For example:

In: The previous attempt failed because the end-effector stalled ~0.27 m laterally from the bowl and never closed the gripper, so drive to the bowl's x,y first, then descend and close to grasp. What action should the robot take to pick up the black bowl ...?

What I built

ML Infrastructure

LLM-driven failure diagnosis

Replaced hand-typed diagnoses with an automated LLM call on every captured failure. Each call reads that failure's simulator state, so the diagnoses scale with the data instead of the team's time.

Fine-Tuning

LoRA fine-tuning pipeline

Built a synthetic reflection dataset from the final 30–50% of successful LIBERO demonstrations, then LoRA-fine-tuned OpenVLA-7B on Modal (rank 32, 2,000 steps, mixed with the original demonstrations). This ruled out the possibility that the feedback prompt was simply unfamiliar to the model.

Experiment Design

Control arm & prompt plumbing

Implemented the control-condition evaluation, moved the feedback into a dedicated prompt-prefix slot (fixing a double-wrapped prompt), and tagged every run's condition in both the log filename and the log body, so paired trajectories can be audited.

Robotics

Second VLA integration (G0.5)

Brought up Galaxea's G0.5 (2B parameters, Qwen backbone) on Modal with a batched WebSocket policy server and client, and its own LIBERO evaluation and reflection loop. Along the way I worked out checkpoint dependencies the upstream docs don't mention.

Benchmarking

Cross-architecture baselines

Reproduced LIBERO baselines for five VLA families across four task suites. These set how much failure headroom each model leaves for recovery methods to work with.

Controlled experiment

Across 100 matched pairs, reflection and control produced the same outcome on every episode. That bounds the effect of prompt-based feedback to at most 3.0 percentage points on overall task success (95% confidence), which points future effort toward training-time methods.

Language-ability probe

Given identical frames and prompts, the base vision-language model writes a coherent failure diagnosis, but the action-fine-tuned checkpoint no longer can. This independently reproduces the catastrophic-forgetting effect reported by Hancock et al. (ICLR 2025) and lines up with the "linguistic blindness" observed by Zhang et al. (2026).

What broke, and how I fixed it

Replays didn't reproduce the original failures

Symptom
With no feedback at all, replaying a failed episode reproduced the failure only 44–56% of the time, so about half of any "recoveries" were noise.
Cause
LIBERO's env.seed() only reset NumPy's global random state. The replay loop skipped episodes, so each one consumed a different number of random draws than in the original run, and the policy's PyTorch random state was never reset at all.
Fix
Reseed NumPy and PyTorch with set_seed_everywhere(episode_idx) before every env.reset(). Divergences dropped to 0/5, then 3/33 on a larger batch; the remainder comes from non-deterministic GPU float accumulation.

The feedback prompt was wrapped twice

Symptom
Appending the feedback to the task prompt produced a malformed, doubly wrapped In: … Out: template, so the model never saw the prompt format it was trained on.
Fix
Gave the feedback its own prompt-prefix slot ahead of the task, and logged the exact prompt whenever feedback is active, so every run can be checked.

Runs couldn't be told apart

Symptom
Log files carried no condition labels, so there was no way to confirm which reflection run matched which control run.
Fix
Stamped each run's condition into both the log filename and the log body.

G0.5 wouldn't load

Symptom
The G0.5 checkpoint failed to load on Modal.
Cause
It needs a Qwen processor folder and an action-tokenizer file at paths its documentation never mentions.
Fix
Traced the expected path through the checkpoint's config.yaml and documented the setup for the team.

What I learned

  • Check the measurement before the result. Before the seeding fix, half the apparent recoveries were replay noise. Now I validate the setup on a case with a known answer first.
  • Rule out the easy explanation. Fine-tuning on the feedback prompt removed "the model has never seen this prompt" as an explanation, which made the result much more meaningful.
  • Correction belongs in training. The results point to building simulator-generated diagnoses into training (APO/DPO-style preference optimization or attention recalibration) rather than adding them to the prompt at deployment.
